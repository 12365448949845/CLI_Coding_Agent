# Windows 工具兼容性修复 Spec

## 背景

ch03 已为 MewCode 提供固定六工具和单轮工具闭环，但 Windows 实际使用中暴露出三类问题：命令输出可能采用当前系统代码页，而程序按 UTF-8 解释后产生乱码；模型不知道当前操作系统、shell 和工作目录，可能生成不兼容的 POSIX 命令；模型可能编造未注册工具或使用当前文件匹配工具不支持的模式。

本次修复保持 ch03 的单轮工具边界，不加入 Agent Loop。

## 目标

- Windows 命令的中文输出能够正确显示并回灌给模型。
- 模型明确知道当前操作系统、shell 和工作目录。
- 模型只陈述并调用实际注册的六个工具。
- 模型生成与当前平台、当前工具参数能力兼容的调用。

## 功能需求

- F1：命令输出解码
  系统应正确显示并回灌 UTF-8 及 Windows 当前代码页产生的标准输出和错误输出，不出现因错误解码产生的替换字符乱码。

- F2：运行环境上下文
  每次请求都应让模型知道当前操作系统、shell 类型和工作目录。

- F3：准确工具清单
  模型只能把实际注册的六个工具声明为可用工具：`read_file`、`write_file`、`edit_file`、`bash`、`glob`、`grep`，不得编造 `ToolSearch` 等未注册工具。

- F4：平台兼容命令
  模型使用 `bash` 时，应根据当前 shell 生成兼容命令；Windows 默认使用 `cmd.exe` 语法，不生成 `pwd`、`ls` 等 POSIX 命令。

- F5：兼容的文件模式
  模型使用 `glob` 时只能采用工具实际支持的模式，不使用 `{py,json}` 等 brace expansion；需要匹配多类文件时，可在首批请求中发起多个合法 glob 调用。

- F6：单轮边界反馈
  继续保持“一批工具执行 + 一次续答”的限制。续答再次请求工具时，不执行第二批工具，并向用户显示清晰的中文限制提示，不得静默结束。

## 非功能需求

- N1：兼容性
  UTF-8 输出行为不得回归；Windows 本地代码页输出应自动兼容，Linux 和 macOS 继续按 UTF-8 正常工作。

- N2：界面稳定
  解码和环境上下文构造不得阻塞流式响应或工具执行，TUI 在等待期间保持响应。

- N3：安全性
  注入模型的运行环境只能包含操作系统、shell 和工作目录，不包含 API 密钥、环境变量值或其他敏感信息。

- N4：上下文准确性
  运行环境信息应取自当前进程的真实状态，不能写死为 Windows，也不能因切换运行目录而继续使用过期值。

- N5：行为兼容
  不改变六个工具的公开参数 Schema、注册顺序、超时和结果截断规则；现有 Anthropic 和 OpenAI 协议行为保持一致。

- N6：可验证性
  编码回退、环境注入、工具清单约束、平台命令约束和单轮提示都必须有自动化测试。

## 不做的事

- 不加入 Agent Loop；工具结果回灌后仍只允许一次续答。
- 不新增 `ToolSearch` 或动态工具发现机制。
- 不新增 PowerShell、Git Bash、WSL 等 shell 选择功能；Windows 继续使用当前默认的 `cmd.exe`。
- 不自动把 POSIX 命令翻译成 Windows 命令；通过环境上下文和工具约束引导模型生成正确命令。
- 不为 `glob` 增加 brace expansion；模型必须使用现有支持的模式。
- 不增加输出编码配置项；本次采用自动识别与系统代码页回退。
- 不修改权限、安全沙箱、路径白名单或工具确认机制。
- 不处理单个命令同时混合多种字符编码的特殊输出。

## 验收标准

- AC1（F1）：在 Windows 下执行产生中文本地代码页输出的命令，工具结果中文字可读且不包含 `�`；UTF-8 中文输出同样保持正确。
- AC2（F2）：捕获一次模型请求，能观察到其中包含真实的操作系统、shell 类型和当前工作目录；改变当前目录后，新请求中的目录随之更新。
- AC3（F3）：询问“你有哪些工具”时，答复只列出实际注册的六个工具，名称与注册表一致，不出现 `ToolSearch`、`ReadFile` 等错误名称。
- AC4（F4）：Windows 环境上下文明确说明使用 `cmd.exe` 语法；用当前 DeepSeek 配置询问项目入口时，首批工具调用不再使用 `pwd`、`ls` 等 POSIX 命令。
- AC5（F5）：模型收到的约束明确说明 `glob` 不支持 brace expansion；查找多种扩展名时不产生 `*.{py,json}` 形式的调用。
- AC6（F6）：模拟续答再次请求工具，系统不执行第二批工具，并在 TUI 显示中文单轮限制提示，不出现工具结果后静默结束。
- AC7（综合）：在 Windows TUI 中询问项目入口，命令输出无乱码，工具行和结果摘要正常显示；若任务需要第二批工具，则显示明确限制提示并恢复输入状态。
- AC8（回归）：全部既有测试、lint、格式检查和类型检查通过；Anthropic 和 OpenAI 的工具定义注入与结果回灌行为不回归。
